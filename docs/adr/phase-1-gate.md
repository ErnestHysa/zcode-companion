  rpc-frame fragment/assemble codec, relay JSON models.

  executing `packages/rpc/src/{serialization,protocol}.ts` + `packages/shared/.../wire-binary.ts`

  framing, chunk-stream drains, CRC32 incl. IEEE check value `cbf43926`, channel shapes,

## 3. Exit-gate check — why BLOCKED

Phase-Level Acceptance Criteria (§43.2 Phase 1): *"All spike questions YES; sanitized
corpus committed; Q1/Q2/Q3/Q4/Q9/Q10 answered with evidence; INV-15/16 upheld."*

| Item | State |
|---|---|
| connect / auth / receive / decode / safe request / event + recovery (the six spike questions) | YES **against a protocol-faithful mock**; NO for the production relay — the live leg is unexecuted |
| sanitized corpus committed | **missing** (live capture pending; capture+redact pipeline ready and tested) |
| Q1 fragment/ack schedule | **partial**: message names + schema + limits recovered from the shipping bundle (`rpc-frame-ack`/`ackMessageSeq`, 64×1 MiB/16 MiB/30 s); live cadence pending |
| Q2 QR `t` expiry | **pending live probe** (bundle evidence says `t` never reaches the relay — confirm live) |
| Q3 nonce policy | **pending live probe** (nonce-per-challenge confirmed in bundle; server reuse semantics need live observation) |
| Q4 `mid`/`name` validation | **pending live probe** |
| Q9 bootstrap schemas | **schemas extracted** `[VERIFIED]`; live payload capture pending |
| Q10 second-terminal behavior | **pending live probe** (mock intentionally does not enforce single-terminal) |
| INV-15/16 | **UPHELD**: no live traffic captured; no credentials/QRs/content in repo; probe material handled only in memory or `$TMPDIR`; redaction lint active |

**The blocker is input, not engineering**: the terminal-role handshake requires the
pairing passHash, which exists only (a) inside freshly generated QR codes (desktop UI) and
(b) inside the desktop's encrypted credential envelope. Decrypting (b) outside the
desktop's own flow would violate the credential custody boundary and would weaken the
spike's evidentiary premise ("an independent client holding QR material can authenticate",
§47.1); driving the user's desktop UI autonomously was rejected as invasive. The
architecture itself schedules this as a *manual probe window* with the user's desktop
(§43.2 Phase 1 preconditions).

**Unblock action (user, ~2 minutes)**: open ZCode desktop → Mobile Remote Control → copy
the link → provide it to the spike via `SPIKE_QR_URL` (or `--qr`). Then run, in order:
`spike --stage auth`, `--stage negative-proof`, `--stage discover`, subscribe stage,
`--stage recover --loops 10`, `--stage double-terminal`; capture per
`docs/runbooks/capture.md`; redact; validate; commit fixtures; update §46 answers here.
No production UI is started before this gate passes (binding rule §43.0 — respected).
